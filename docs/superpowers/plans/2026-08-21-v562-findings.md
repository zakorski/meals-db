## Task 2: Item 3 — baseline confirmation on the deactivate path

**Files:** Modify `includes/class-clients.php` (a display-name helper); `includes/ajax/class-ajax-clients.php` (always `needs_confirm` when unconfirmed)

- [ ] **Step 1: Add a display-name helper to `MealsDB_Clients`**

Next to `recent_order_summary`:

```php
    /** "First Last" for a client id, or '' if unknown. Used in confirm dialogs. */
    public static function display_name(int $client_id): string {
        global $wpdb;
        $table = MealsDB_DB::get_table_name(MealsDB_Tables::CLIENTS);
        $row = $wpdb->get_row($wpdb->prepare(
            "SELECT first_name, last_name FROM `{$table}` WHERE client_id = %d LIMIT 1",
            $client_id
        ), ARRAY_A);
        if (!$row) { return ''; }
        return trim((string) ($row['first_name'] ?? '') . ' ' . (string) ($row['last_name'] ?? ''));
    }
```

- [ ] **Step 2: Always require confirmation on an unconfirmed deactivate**

        $confirmed = isset($_POST['confirm']) && $_POST['confirm'] === '1';

                        (string) $recent['last_date']

                ]);

            // v562 ITEM 3: baseline confirm even with NO recent orders —
            // deactivation silently removes the client from Quick Order search
