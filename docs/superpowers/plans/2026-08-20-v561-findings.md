> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the v561 verification findings — enqueue the select2 stylesheet, reject malformed approve dates server-side, surface silent PO no-ops, and make orders reactivate a deactivated client (with a deactivation guard + audit).

**Architecture:** Item 1 registers WooCommerce's select2 style ourselves (WC only registers it on its own screens). Item 2 rejects provided-but-invalid `expected_arrival` in `approve()` instead of silently defaulting; the input gets `min`/`max`/hint. Item 3a makes `msg()` scroll into view; Item 3b flushes pending row saves before Complete. Item 4 reactivates a deactivated client on a qualifying new order (before allocation runs, so the recalc active-filter can't skip them), warns on deactivation with recent orders, and audits reactivation.

**Tech Stack:** PHP 8.2 / WordPress admin / WooCommerce (HPOS) / vanilla-jQuery. Tests: the repo's in-memory harness (`php tests/<file>.php`); JS/CSS gated by `node --check`/`php -l` + the directive's screenshot checklist.

**Source directive:** `directives/DIRECTIVE-v561-findings.md` (baseline v1.0.561). **This resolves the v560 Item 7 client-search mystery (it was `active = 0`).**

### Verified facts that shape the build
- **Item 1:** `wp_enqueue_style('select2')` is guarded on `wp_style_is('select2','registered')`, which is false on our page (WC registers the style only on its own screens). Register it ourselves first.
- **Item 2:** `approve()` does `normalize_date()` → null on malformed → treated as blank → silent default. The detail view uses `<input type=date>` (no `prompt()`); the server has never validated. Fix in `approve()`.
- **Item 3a:** all-zero approve **already** returns `WP_Error('empty')` and the handler **already** `msg()`s it — so this is `msg()` VISIBILITY (single `#mealsdb-po-action-msg`, top of the list view), not a missing branch. Fix = scroll it into view.
- **Item 3b:** reconcile notes save via a **separate debounced** `edit_reconcile_row`; `complete_reconcile` validates the **server-stored** note. Complete before the debounce flushes → spurious `notes_required`. Fix = flush pending saves, then complete.
- **Item 4:** `active = 0` is written ONLY by the manual admin deactivation path (`ajax-clients.php`), never by sync/cron — so reactivation won't ping-pong. `MealsDB_Clients::activate_client()` exists. `on_order_created` already resolves the order's customer + date and runs fees→allocate; reactivating **before** that means the recalc's `active_only` filter can't skip the just-reactivated client.

### Not in this build
Item 4 SQL cleanup is delivered as an operator runbook (not executed). The "Not in this build" directive items (SDNB datasheet, zoneless-clients, PO backdating, staging cleanup) are left alone. Item 4d SQL → runbook.

- [ ] **Step 3: Add a validator + reject provided-but-invalid in `approve()`**

Add a private helper near `normalize_date` / `po_schedule_from_order_date`:

```php
    /**
     * A supplied expected-arrival date is valid only if it is a real calendar
     * date in YYYY-MM-DD within about a year (a PO arrives soon). Format alone
     * isn't enough — the browser's date input can emit a 6-digit year
     * ('152026-09-09') that passes a naive regex, and normalize_date() accepts
     * impossible dates like 2026-13-40. Reject those rather than silently
     * substituting the computed default (v561 ITEM 2).
     */
    private static function is_valid_arrival(string $ymd): bool {
        if (!preg_match('/^(\d{4})-(\d{2})-(\d{2})$/', $ymd, $m)) {
            return false;
        }
        if (!checkdate((int) $m[2], (int) $m[3], (int) $m[1])) {
            return false;
        }
        $year = (int) $m[1];
        $now  = (int) gmdate('Y');
        return $year >= $now - 1 && $year <= $now + 1;
    }
```

- [ ] **Step 2: Add the pure month helper to `MealsDB_Clients`**

```php
    /**
     * True iff $order_ymd (YYYY-MM-DD) falls in the same month as $today_ymd or
     * the immediately preceding month. Used to decide whether an order is recent
     * enough to reactivate a dormant client (v561 ITEM 4b) — a years-old import
     * must not resurrect anyone. Anchored on month arithmetic, DST-proof.
     */
    public static function order_month_qualifies(string $order_ymd, string $today_ymd): bool {
        if (!preg_match('/^\d{4}-\d{2}-\d{2}$/', $order_ymd) || !preg_match('/^\d{4}-\d{2}-\d{2}$/', $today_ymd)) {
            return false;
        }
        $om = substr($order_ymd, 0, 7);
        $cur = substr($today_ymd, 0, 7);
        $prev = gmdate('Y-m', strtotime(substr($today_ymd, 0, 7) . '-01 -1 month'));
        return $om === $cur || $om === $prev;
    }
```

- [ ] **Step 3: Add the reactivation method**

Add to `MealsDB_Clients` — resolves the client by wp_user_id, applies the three guards, reactivates, and audits with the order id:

```php
    /**
     * Reactivate a deactivated client when a qualifying order arrives (v561
     * ITEM 4b/4c). ALL must hold: the order is non-cancelled/refunded; its date
     * is in the current or previous billing month; the client exists and is
     * currently inactive. Audited as 'client_reactivated' carrying the order id
     * so it's never a mystery why someone reappeared on an invoice.
     *
     * @return bool true if a client was reactivated.
     */
    public static function maybe_reactivate_on_order(int $wp_user_id, string $order_ymd, string $order_status, int $order_id): bool {
        if ($wp_user_id <= 0) { return false; }
        $status = ltrim((string) $order_status, 'w'); // tolerate 'wc-...' or bare
        $status = preg_replace('/^c-/', '', $status);
        if (in_array($status, ['cancelled', 'refunded', 'failed', 'trash'], true)) {
            return false;
        }
        if (!self::order_month_qualifies($order_ymd, current_time('Y-m-d'))) {
            return false;
        }
        global $wpdb;
        $table = MealsDB_DB::get_table_name(MealsDB_Tables::CLIENTS);
        $row = $wpdb->get_row($wpdb->prepare(
            "SELECT client_id, active FROM `{$table}` WHERE wp_user_id = %d LIMIT 1",
            $wp_user_id
        ), ARRAY_A);
        if (!$row || (int) $row['active'] === 1) { return false; }
        $client_id = (int) $row['client_id'];
        if (!self::activate_client($client_id)) { return false; }
        if (class_exists('MealsDB_Logger')) {
            MealsDB_Logger::log('client_reactivated', $client_id, 'active', '0', '1', 'order:' . $order_id);
        }
        return true;
    }
```

- [ ] **Step 1: Add a recent-order summary helper**

In `MealsDB_Clients` — count non-cancelled orders in the current/previous billing month and the latest date. HPOS-safe via `wc_get_orders`:

```php
    /**
     * Non-cancelled orders for a client in the current or previous billing month
     * (v561 ITEM 4a). Used to warn before deactivating someone who is still
     * ordering. Returns ['count' => int, 'last_date' => 'Y-m-d'|''].
     */
    public static function recent_order_summary(int $client_id): array {
        $out = ['count' => 0, 'last_date' => ''];
        global $wpdb;
        $table = MealsDB_DB::get_table_name(MealsDB_Tables::CLIENTS);
        $uid = (int) $wpdb->get_var($wpdb->prepare("SELECT wp_user_id FROM `{$table}` WHERE client_id = %d LIMIT 1", $client_id));
        if ($uid <= 0 || !function_exists('wc_get_orders')) { return $out; }
        $prev_start = gmdate('Y-m-01', strtotime('first day of last month'));
        $orders = wc_get_orders([
            'customer_id' => $uid,
            'limit'       => -1,
            'status'      => ['pending', 'processing', 'on-hold', 'completed'],
            'date_created' => '>=' . $prev_start,
            'return'      => 'objects',
        ]);
        $last = '';
        foreach ($orders as $o) {
            $out['count']++;
            $d = $o->get_date_created();
            if ($d) { $ymd = $d->date('Y-m-d'); if ($ymd > $last) { $last = $ymd; } }
        }
        $out['last_date'] = $last;
        return $out;
    }
```
